# Full-paper acquisition and structured extraction

Research snapshot, 2026-11-07. Primary documentation and repository pages were inspected via web search and source excerpts; no model weights were downloaded and no parser was executed. Repository default branches and model catalogs change, so pin versions and recheck terms before use. This is an architectural recommendation, not a measured ranking or legal advice.

## Recommendation

Use **versioned arXiv LaTeX source plus PDF**, with native arXiv HTML where available as a navigable secondary representation. Preserve and inspect the entire source tree, including appendices, bibliography, included files, tables and graphics. Use **LaTeXML** when structured expansion is useful, keeping the raw TeX as the authoritative source. For missing or unusable source, use **Docling's structured PDF output** as the initial fallback, retaining page-level evidence and the original PDF. Independently check critical numeric claims against the rendered PDF. Add GROBID only if reference/citation parsing becomes important; compare Marker, MinerU and olmOCR on difficult cases before introducing another runtime. These selections are hypotheses until measured on the landscape corpus.

This stack is minimal in deployment count, not a claim that Docling is the most accurate parser. Raw TeX can contain macros, conditional text, external files and tabular constructions that a simple regex cannot resolve; HTML and generated XML can also silently omit or distort content. None automatically establishes a verified TeX-to-PDF page mapping.

## Acquisition and representations

1. Resolve identifier and **explicit version**, canonical abstract URL, submission date, DOI if any, license and acquisition timestamp. Fetch the matching source and PDF; `~/bin/arxiv-src <id-or-url>` is a local acquisition helper, whose behavior and installed dependencies need inspection before integration. arXiv source downloads can be an archive, a single source file, or unavailable; validate file type, safely unpack without path traversal or links escaping the directory, record failures and hash original bytes. Do not run untrusted TeX, shell escape, or document converters with ambient secrets/network access; use isolation and resource limits.
2. Inventory the root document, `\input`/`\include`, bibliography, appendices, tables, figures and custom macros. Preserve raw files, hashes and relative paths. Resolve include graphs without assuming source order equals reading order. Flag missing includes, generated `.bbl` versus `.bib`, unsupported packages, errors and incomplete conversion. LaTeXML converts TeX to XML and then HTML/MathML; it is a Perl-based converter, and its [manual](https://math.nist.gov/~BMiller/LaTeXML/manual.pdf) documents bibliography, cross-references and graphics processing. [Code license](https://github.com/brucemiller/LaTeXML/blob/master/LICENSE): public-domain dedication, described as CC0-equivalent. Exact packaging and sandbox behavior on DGX remain unverified.
3. Check the abstract page for official HTML, rather than assuming it exists for every paper or version. arXiv describes HTML as experimental, incrementally backfilled and subject to conversion failures ([arXiv HTML](https://info.arxiv.org/about/accessible_HTML.html)). [ar5iv](https://ar5iv.labs.arxiv.org/) is a separate LaTeXML conversion project, not a live version-complete substitute; its landing page says only one version per article is available. Confirm the version before treating either HTML view as evidence.
4. On PDF-only or deficient TeX/HTML cases, retain Docling JSON alongside any Markdown, source PDF and page images/crops as permitted. Do not treat reconstructed formulas, captions or table cells as ground truth. A targeted second parser or manual inspection is appropriate for low-confidence pages; preserve disagreement rather than silently merging.

For discovery and transport, arXiv's [API terms](https://info.arxiv.org/help/api/tou.html) distinguish metadata from papers. [Bulk guidance](https://info.arxiv.org/help/bulk_data.html) recommends OAI-PMH for bulk metadata and S3 for bulk full text; avoid corpus-wide scraping. Respect endpoint-specific current limits and backoff; API rate limits should not be assumed to apply identically to every download endpoint. Version-specific API and source URL behavior, including availability and redirects, must be checked in a small acquisition pilot.

## Evidence contract for extraction

Keep one immutable paper/version record with source URI, retrieval time, license indication, content hashes and parser/model/configuration versions. For every extracted assertion, retain **multiple evidence spans where needed**, plus status `verified`, `needs_review`, or `unsupported`:

- TeX: archive hash, relative file path, byte or line range in the exact file, verbatim source excerpt and relevant macro definitions; figure/table label and include path where present. A line range is not a PDF coordinate. Preserve macro expansion and raw source separately.
- HTML/XML: URL or artifact hash, version, stable element ID or selector and exact text/MathML; if IDs are missing or generated, retain a text quote and surrounding context. HTML anchors are representation-specific and may change after reconversion.
- PDF: PDF hash, 1-based physical page, printed page label if known, bounding box and coordinate convention/page dimensions, plus visible excerpt or crop. Distinguish parser-produced locations from human-verified locations. A multi-page table may require several regions. If no box is available, explicitly record page-only evidence.
- Link representations only when independently matched; never fabricate page numbers from source order. Record exact quoted text separately from normalized interpretation. Check captions, footnotes, headers, units, evaluation protocol, uncertainty and appendix qualifications; figure curves need visual review, not invented precise values.

A result row should identify paper/version, model and variant, dataset/split, task, metric/direction, value and uncertainty, unit, evaluation protocol, training or pretraining data, backbone/scale where relevant, comparison baseline and source locations for both value and context. Preserve author-reported values and formatting separately from normalized numbers; distinguish missing, not reported, inapplicable and ambiguous. Contributions, limitations and future work should carry verbatim supporting spans, attribution and scope: author-stated versus analyst inference; absence of an explicit limitations section is not evidence of no limitations. Include negative or null findings and competing evidence.

## Benchmark design

Build a manually adjudicated, version-pinned JEPA sample, stratified by source availability, year, model family, conference layout and difficulty. Target 30 papers initially, including PDF-only, multi-file TeX, appendix-heavy papers, multi-column layouts, complex/multi-page tables, mathematical definitions and plots. Report counts per stratum; if the corpus lacks a stratum, supplement with clearly labeled non-JEPA controls. Split by paper/family and keep a held-out set for final comparison to limit tuning leakage. Two reviewers independently annotate a subset and adjudicate disagreements; report agreement and preserve the annotation protocol.

Compare identical source versions and the same downstream extraction model, prompt, decoding and evidence schema across: (A) TeX plus available HTML, (B) Docling PDF, (C) the combined routing policy, and (D) one or more challenger PDF parsers on the same subset. Add an oracle/manual-transcription input to separate parser damage from reasoning errors. Log unavailable/failed inputs and treat them as failures in end-to-end coverage, not as excluded successes. Use no external LLM service without checking full-text permissions and data-handling terms.

Score separately:

1. **Acquisition/structure:** full-paper and appendix coverage, successful conversion, missed pages/sections, table/figure detection and reading order.
2. **Result rows:** row precision/recall/F1 against annotated rows; exact numeric/sign/uncertainty and unit accuracy; correctness of model, metric, dataset, split, protocol and baseline; complete-row exact match. Include macro-averaged per-paper results and bootstrap paper-level intervals. Detect plausible but wrong header-to-cell association.
3. **Claims:** contribution/limitation/future-work precision and recall, faithful scope and attribution, plus unsupported-claim rate. Annotate acceptable paraphrases and partial matches before scoring; use human adjudication rather than only LLM judging.
4. **Grounding:** proportion of claims whose cited locations resolve, actually support every field and cover qualifying context; report page-only versus precise-span/box separately. Measure false evidence links and abstention/coverage tradeoff.
5. **Operations:** wall time/page, CPU/GPU and peak RAM/VRAM, model size, error/retry rate, cost and license/dependency burden. Lock versions, hardware, parser settings, random seeds and downstream model; record failures and repeat nondeterministic runs.

Require manual review for conflicting values, missing qualifiers, weak grounding and plots. Report per-stratum errors, not only a single aggregate; select a stack based on verified end-to-end accuracy and coverage, not generic OCR leaderboard scores.

## Rights and unresolved verification

arXiv's [API terms](https://info.arxiv.org/help/api/tou.html) make descriptive metadata CC0, while e-prints retain copyright. Its [bulk policy](https://info.arxiv.org/help/bulk_data.html) says the common non-exclusive arXiv distribution grant does not authorize downstream redistribution and full-text indexes should link back for downloads. Check the actual paper version's license and any third-party figure permissions; even an open paper license may not cover every embedded figure. CC licenses vary, including attribution, noncommercial and share-alike requirements. Other providers' metadata and abstracts have their own terms; do not generalize arXiv CC0 to them. Short quotations, derived rows and figure crops also need a context-specific rights assessment; do not assume extraction or a citation grants republication rights. Keep restricted source and derived artifacts access-controlled, and publish links and appropriately licensed outputs only. This is not a determination of fair use or text/data-mining exceptions.

Before deployment, verify exact source/HTML version behavior, safe archive handling, chosen model cards and transitive licenses, container image architectures, Python/native wheels, GPU drivers/CUDA and GB10 compatibility; benchmark conversion completeness and ground-truth alignment. No runtime compatibility, speed, accuracy, or legal clearance was verified in this research.
